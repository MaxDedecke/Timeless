# Design-Rückblick auf Sprint 9

Sprint 9 wirkt aus Design-Sicht stimmig: Der No-Show-Status ist in Raumkalender und Tagesansicht durchgängig im selben Stil umgesetzt (Muted-Fläche, gestrichelter Rand, Badge „Nicht erschienen“), und die konfigurierbare Frist wird sauber vom Backend über die API bis zur Check-in-Sichtbarkeit im Frontend gereicht, inklusive dokumentiertem Default-Fallback. Stark ist, dass beide neuen Konzepte auf etablierte Muster zurückfallen – BookingStatusBadge für den Genehmigungsstatus, die dokumentierten Lade-/Fehler-/Leerzustände, Bestätigungsdialog statt Eigenbau – die Referenz in docs/design-konzept.md greift damit sichtbar. Eine Schnittstelle ist noch ungeregelt: Der TimeGrid-Kalenderslot bekommt mit Status-Badge und dem im Gäste-Konzept vorgesehenen Gäste-Badge zwei Badge-Klassen, deren Zusammenspiel (Reihenfolge, Kürzung, schmale Breiten) kein Ticket regelt – das vor der Gäste-Umsetzung festzulegen verhindert erneut zwei leicht unterschiedliche Lösungen desselben Elements. Beachte zudem: /approvals ist erreichbar, aber die API liefert 404; der Fehlerzustand ist korrekt implementiert, sollte im Review aber als bekannte Einschränkung bis zum Backend-Ticket kommuniziert werden. Für den nächsten Sprint gilt: Gäste-Erfassung und Genehmigungsliste streng nach Konzept umsetzen, sobald die Backend-Tickets dazu laufen.
